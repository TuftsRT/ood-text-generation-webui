# Text Generation WebUI — Open OnDemand App

An [Open OnDemand](https://openondemand.org/) Batch Connect app that launches
[text-generation-webui](https://github.com/oobabooga/text-generation-webui) on a
GPU node of the Tufts HPC cluster (`pax`). It appears in the dashboard under
**Interactive Apps → AI**.

The WebUI runs inside a Singularity container, and the session card gives you a
**Connect to Text Generation WebUI** button plus a username and a password
generated for that session.

## Using the app

1. Open the [Tufts OnDemand dashboard](https://ondemand-prod.pax.tufts.edu/) and
   choose **Interactive Apps → text-generation-webui**.
2. Fill in the form:

   | Field | Description |
   | --- | --- |
   | Number of hours | Wall time for the job. The maximum is set by the chosen partition. |
   | Number of cores / Memory (GB) | CPU and RAM. The maximums depend on the partition and GPU type. |
   | Partition | GPU partitions you have access to. |
   | GPU type | GPU model/variant, filtered to what the chosen partition offers. A warning appears if the selected type is currently unavailable. |
   | Version | Container version (currently `3.10`). |
   | Model directory | Directory of models to load. The default, `/cluster/tufts/hpc/tools/text-generation-webui/models`, holds commonly used models. You can point it at your own directory instead. |
   | User Data directory | Where settings, characters, presets, etc. are stored. Default: `$HOME/text-generation-webui/user_data`. |
   | Request priority start | Submits with `--qos=interactive` so the job starts sooner. While it is checked, the resource fields are capped to the interactive QOS limits. |

3. Click **Launch**. When the session is running, click **Connect** and log in
   with the username and password shown on the session card. Startup can take
   about a minute after the job begins.

## How it works

| File | Purpose |
| --- | --- |
| `manifest.yml` | App name, category, and description shown in the dashboard. |
| `form.yml.erb` | Form definition. Partition, GPU, core, memory, and hour fields are generated by the shared partial `/etc/ood/config/apps/dashboard/batch_connect/partials/resource_discovery.erb`. |
| `form.js` | Client-side form logic: repopulates GPU types per partition, hides GPU fields for CPU-only selections, adjusts core/memory/hour limits, and warns about unavailable GPUs. |
| `submit.yml.erb` | Slurm submission: time, cores, memory, partition, `--gres`/`--constraint` built from the GPU type, and QOS from the shared `partition_qos.rb`. Sends email on job start and end. |
| `template/before.sh.erb` | Picks a free port and generates the session password. |
| `template/script.sh.erb` | Seeds the user-data directory from `/cluster/tufts/apps/container/ngc/ai/text-generation-webui/user_data`, loads `singularity`, and runs `/cluster/tufts/apps/container/ngc/images/text-generation-webui_<version>.sif` with the model and user-data directories bind-mounted and Gradio authentication turned on. |
| `template/after.sh.erb` | Waits briefly before the Connect button appears so the server has time to start. |
| `view.html.erb` | Connect button and login credentials shown on the session card. |
| `icon.png` | Dashboard icon. |

### Dependencies outside this repo

- Shared partials on the OnDemand host:
  - `/etc/ood/config/apps/dashboard/batch_connect/partials/resource_discovery.erb`
  - `/etc/ood/config/apps/dashboard/batch_connect/partials/partition_qos.rb`
- Container images: `/cluster/tufts/apps/container/ngc/images/text-generation-webui_<version>.sif`
- Default user data: `/cluster/tufts/apps/container/ngc/ai/text-generation-webui/user_data`
- Shared models: `/cluster/tufts/hpc/tools/text-generation-webui/models`

## Development

To test changes, use OnDemand's sandbox apps: clone this repository into
`~/ondemand/dev/` and open it from **Develop → My Sandbox Apps** in the
dashboard. To add a container version, put the new `.sif` image in the images
directory and add its version to the `version` options in `form.yml.erb`.
